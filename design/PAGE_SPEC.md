# Page Specification

This spec forces authored composition and scan hierarchy across every page. Signature motif: Orchestration Ledger.

## 1) Homepage

## Purpose

State a point of view in the first screen, then prove Dave can execute it.

## Section order

1. Decision Review Board (first viewport)
2. Proof strip (hard outcomes)
3. Friction classes (what work is worth redesigning)
4. Method as ledger sequence (01 to 05)
5. Work evidence index
6. Counterpoint band: where AI should stop
7. Writing as active research log
8. Strategy-to-implementation bridge
9. Contact handoff protocol

## Visual composition

- Risky opening: 4/8 split where 8-column Decision Review Board is primary visual mass.
- Vertical ledger spine runs through first three sections and is allowed to break section boundaries.
- Alternating density: dense evidence block followed by quiet explanatory block.

## Notable interactions

- Global Failure Mode Lens toggle affects visible state in this page.
- On first screen, each board row has a hover/focus "evidence note" reveal.

## 5-second scan

- "This is about designing decision ownership, not selling AI services."

## 30-second scan

- User sees problem classes, method sequence, and proof outcomes.

## 3-minute reading

- User can trace from thesis to practical constraints and choose a next step.

## Desktop behavior

- Decision Review Board remains above fold.
- Side ledger annotations are visible and clickable.

## Mobile behavior

- Board stacks into accordion rows with fixed row labels.
- Ledger spine becomes horizontal stage chips.

## 2) Work / Projects

## Purpose

Make competence inspectable through repeatable project anatomy.

## Section order

1. Page thesis and filter intent
2. Project ledger index
3. Constraint legend and confidence key
4. CTA to discuss analogous workflow

## Visual composition

- No equal card wall.
- Repeating 8/4 and 4/8 rhythm between projects.
- Every project preview includes boundary stamp and evidence seal.

## Notable interactions

- Failure Lens on: each card expands exception details inline.
- Filter chips progressively enhance by URL params.

## 5-second scan

- "Real implementation evidence, not a portfolio gallery."

## 30-second scan

- Compare outcomes and constraints across project types.

## 3-minute reading

- Understand trade-offs and click into deep case material.

## Desktop behavior

- Mixed-width cards with one featured project every third item.

## Mobile behavior

- Single-column cards with tap-to-reveal detail rows.

## 3) Individual Case Study

## Purpose

Show how decisions were made, tested, and constrained.

## Section order

1. Situation and business pressure
2. Before/after workflow map
3. Ownership boundaries
4. System diagram
5. Implementation notes
6. Outcomes and confidence
7. Failure modes and overrides
8. Next iteration options

## Visual composition

- Main narrative plus right rail for metadata and annotations.
- Diagram blocks occupy full-width breaks to reset reader attention.

## Notable interactions

1. Workflow lane toggle:

- JS required: yes.
- Fallback: both lanes visible.
- Mobile: lanes in stacked accordions.

2. Failure Lens integration:

- JS required: optional if global state already set.
- Fallback: exception content always visible.

## 5-second scan

- Identify domain, core boundary, and outcome.

## 30-second scan

- Understand what changed and how risk was handled.

## 3-minute reading

- Inspect architecture, constraints, and operational implications.

## Desktop behavior

- Sticky metadata rail with scope, timeline, confidence, and owner transitions.

## Mobile behavior

- Metadata folds into top summary rows below header.

## 4) Writing Index

## Purpose

Present writing as active technical research, not passive blogging.

## Section order

1. Publication thesis
2. Featured piece
3. Recent articles by argument
4. Topic lanes
5. Contact/subscribe action

## Visual composition

- Editorial list with side argument labels and ledger marks.
- One high-contrast featured article block.

## Notable interactions

- Hover/focus reveals "why this matters" sentence.
- Topic lane chips filter list with progressive enhancement.

## 5-second scan

- "These are strong technical opinions with implementation relevance."

## 30-second scan

- Themes and stances become clear.

## 3-minute reading

- Reader can navigate depth by topic and argument type.

## Desktop behavior

- Featured article offset with margin annotation block.

## Mobile behavior

- Featured remains first, metadata condensed.

## 5) Individual Article

## Purpose

Support deep, scannable technical argument.

## Section order

1. Title and thesis
2. Strong claim block
3. Argument sections
4. Counterargument/limits
5. Practical checklist

## Visual composition

- Thesis blocks carry boundary stamps when discussing limits.

## Notable interactions

- Heading anchor links on hover/focus.

## 5-second scan

- Understand article claim immediately.

## 30-second scan

- Capture argument arc and practical takeaway.

## 3-minute reading

- Follow nuance and trade-offs with clear wayfinding.

## Desktop behavior

- Margin notes remain in side rail.

## Mobile behavior

- Margin notes become inline callouts after related paragraphs.
